# DevouringBeast — 游戏设计文档 (GDD)

## 1. 执行摘要

- **游戏名称**: DevouringBeast（吞噬兽）
- **类型**: 2D 俯视角 Roguelike × 吞噬 × 星之卡比
- **平台**: Android（移动端竖屏）
- **视角**: 正交投影 + 摄像机旋转（以撒式 2.5D）
- **画风**: Q版可爱，纯白圆球角色，四方向精灵图
- **核心循环**: 移动 → 吸入物品/敌人 → 吐出攻击 / 吞噬升级 → 清场 → 下一波
- **参考游戏**: 以撒的结合（视角）、星之卡比（吞噬）、Hades（肉鸽升级）
- **差异化**: 吸入/吐出/吞噬三合一战斗 + 标签占比影响角色颜色与升级路线

## 2. 游戏玩法

### 2.1 核心循环

```
移动探索 → 发现敌人/物品 → 长按吸入（锥形范围，进度条）
    → 吐出：打包能量球攻击敌人
    → 吞噬：吞入腹中，累积质量，改变颜色，触发升级
        → 升级：根据标签占比三选一肉鸽技能
            → 继续下一波
```

### 2.2 操作方式

| 操作      | 方式                 | 说明                               |
| --------- | -------------------- | ---------------------------------- |
| 移动      | 左侧虚拟摇杆（轮盘） | 八方向                             |
| 吸入/吐出 | 右侧按钮 A           | 共用按钮：口中无物=吸入，有物=吐出 |
| 吞噬      | 右侧按钮 B           | 将口中物品吞入，根据标签获得效果   |

### 2.3 吸入逻辑

- **长按吸入按钮**：在角色前方锥形范围内检测可吸入对象
- **关键层级规则**：吸力只查询 `inhaleableLayer`（Layer 6）。可吸入对象的 Collider 必须位于该层，否则不会进入吸力检测；Layer 只负责候选过滤，不代表对象可以无条件入口。
- **吸入进度条**：角色头顶出现带边框的进度条
  - 前半段：进度条颜色渐变，越来越红，吸力逐渐递增至最大
  - 后半段：吸力保持最大直到进度条结束
- **吸入规则**：
  - 目标必须同时处于 Layer 6、吸入半径和角色前方锥形角度内
  - 存活敌人不能直接入口；吸力转换为伤害，并轻微提升其追逐速度
  - 阵亡敌人和掉落物按吸力、质量及吸入阈值计算牵引速度
  - 达到吸入阈值后仍需进入入口距离，才会加入玩家口中
  - 质量或阈值较高的物品会先被拉近，不会从远处瞬移入口
  - 可一次性吸入多个物品
- **结束条件**：进度条耗尽自动停止，或松手停止

### 2.4 吐出逻辑

- 吸入成功且口中有物品后，按钮切换为"吐出"
- 点击吐出：将口中所有物品打包为一个能量球射出
- 能量球撞击敌人造成伤害
- 分裂技能在命中怪物后，从怪物沿飞行方向的后方生成子弹，并忽略本次命中的怪物
- 到达最大飞行距离后自然销毁

### 2.5 吞噬逻辑

- 点击吞噬按钮：将口中物品吞入腹中
- 吸入进行中不能吞噬；吸入/吐出按钮与吞噬按钮不能同时生效，必须等待当前按键松开
- 吞噬容器记录：升级所需质量、当前质量、各标签占比
- 颜色变化：按标签占比混合角色颜色（占比越高颜色越浓）
- 累计满后升级：恢复白色，根据占比最高的标签触发效果，并提升下一级所需质量
- 前三级需求为 `30 / 50 / 75`，之后按约 `1.35` 倍向上取整递增；超过门槛的进度保留到下一级

## 5. 角色视觉

- **外形**: Q版，可爱，纯白色，圆球，大，长耳朵
- **动画**:
  - 移动时耳朵向后摆动（左右方向可见轮廓和阴影）
  - 口中有东西时身体向下（屏幕方向）鼓胀，极具立体感
  - 身体颜色随吞噬标签占比变化，升级后重置为白色
- **精灵图**: 上、下、左、右四个面
- **摄像机**: 正交投影 + 旋转，实现以撒式 2.5D 视觉

---

## 6. 敌人系统

- **双值机制**: 每个敌人维护一个大值（活体吸入阈值）和一个小值（尸体吸入阈值）
- **死亡行为**: 切换阵亡精灵，停留 10 秒，最后 3 秒闪烁后消失
- **玩家生命**: 基础最大生命为 10 点
- **伤害成长**: 普通怪基础伤害 1 点，每 10 波增加 1 点；精英和 Boss 固定追加 1 / 2 点
- **尺寸规则**: 对象池复用必须恢复标准缩放；视觉最大边低于 1.25 的敌人自动等比放大，大型敌人保持原尺寸

### 7.3 核心设计模式

## 9. 数据流

### 9.1 吸入流程

```
Touch(吸气按钮) → PlayerInhale.StartInhale()
  → 锥形射线检测 (Physics2D.OverlapCircle + 角度过滤)
  → 对每个目标: 判断标签 + 质量 vs 当前吸力
    → 质量 < 吸力: 吸入(移向口中) + 加入吞噬容器
    → 质量 > 吸力: 仅拉近(移向玩家)
  → 进度条更新: InhaleProgressBar (前半段吸力递增、后半段满吸力)
  → 松开/结束: PlayerInhale.StopInhale() → 触发吐出/吞噬逻辑
```

### 9.2 吐出流程

```
Touch(吐出按钮) → PlayerSpit.Spit()
  → 从 SwallowContainer 获取所有物品
  → 打包为 EnergyBall → 实例化 + 设置方向、伤害
  → EnergyBall 飞行 → 碰撞检测 → 触发技能效果链
  → 达最大距离自然销毁
```

### 9.3 吞噬升级流程

```
Swallow() → SwallowContainer.Add(item)
  → 更新各标签占比
  → 更新角色颜色(按占比混合)
  → 检查: currentMass >= requiredMass?
    → YES: LevelUp()
      → 重置颜色为白色
      → 根据最高占比标签 → 展示三选一技能面板
      → 选择后 → RogueSkillManager.AddSkill()
      → 提升下一级 requiredMass
```
